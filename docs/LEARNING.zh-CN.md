# 从冻结的 Haven 基线学习

[English](LEARNING.md) | **中文**

这个仓库被保留为一个适合学习的工程基线。代码是行为的权威；生成表格和可执行门禁是修改统计数字时的权威。不同文档承担不同角色，如果阅读顺序错误，很容易把旧计划误认为当前实现。

## 当前内容

下面这些文档描述冻结后的当前实现：

1. `README.md` — 产品边界、命令、测量结果和限制。
2. `docs/PROJECT_CARD.md` — 一页式设计和权衡摘要。
3. `docs/ARCHITECTURE.md` — 分层、工具通道、状态机和存储。
4. `docs/SECURITY.md` — 信任模型、强制措施和明确缺口。
5. `docs/EVAL.md` 与 `docs/EVAL_LIVE.md` — 已测量的内容，以及这些测量不能证明什么。
6. `course/` — 贯穿实现的引导式阅读路径。

`docs/codebase/` 是当前审计的补充材料，分别从结构、技术栈、测试、集成、约定和已知问题总结同一份代码。易变化的统计数字由生成的 metrics 表负责，不在这些文档中重复维护。

## 历史内容

- `Haven_TUI_Coding_Agent_项目计划.md` 是最初提案，其中的复选框表示计划范围，而不是当前完成度。
- `docs/ROADMAP*.md` 和 `docs/superpowers/{specs,plans}/` 保存实现如何设计和排序。它们开头的状态说明会指出哪些内容后来被代码或 ADR 取代。
- ADR 是不可变的决策历史。后续发现会标注或取代 ADR，但不会改写原始推理。依赖旧结论前，先查看文档顶部的修订链接。
- `docs/POSTMORTEM.md` 和 `docs/EVAL_LIVE.md` 的历史部分保留当时观察到的数字；它们是开发过程的证据，不是当前仓库总量。

## 事实层级

当两段描述看起来不一致时，按下面顺序判断：

1. `src/haven/` 中可执行的策略、契约和运行时行为；
2. 生成的工具 / metrics 表和完整质量门禁结果；
3. 当前的架构、安全、评估和课程文档；
4. ADR，且后续修订优先；
5. 历史路线图、规格、计划、事后复盘和旧测量结果。

仓库通过下面的命令强制这条边界：

```bash
uv run python scripts/gates.py --mode fast  # 文档、格式、lint、类型、分层
uv run python scripts/gates.py --mode full  # 额外包含测试、覆盖率、评估、metrics
```

`docs` 门禁会检查本地 Markdown 链接、文档化的 CLI/TUI 命令面、版本一致性和历史标签。生成的 metrics 与工具表门禁会分别从代码和报告中推导事实。

## 安全练习

先运行完整离线套件。修改代码时，使用分支工作，并把冻结基线作为比较点。最适合的学习顺序是：

```text
策略 + 审批
  -> 工具流水线
  -> 运行循环 + 上下文
  -> 证据门禁
  -> 持久化 + 恢复
  -> TUI presenter
  -> 离线与实时评估报告
```

课程或已提交的测试都不需要 API key。实时练习是可选的、有费用且不可复现的，必须明确确认后才能进行。
